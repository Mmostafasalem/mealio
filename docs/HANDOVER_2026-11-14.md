## How to work here

**Build**

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild \
  -project smartmarket.xcodeproj -scheme smartmarket \
  -destination 'platform=iOS Simulator,name=iPhone 17' build CODE_SIGNING_ALLOWED=NO
```

**Tests** — the suite has been run on the `Mealio Small Screen QA` simulator
(strictest layout) and `iPhone 17`:

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild \
  -project smartmarket.xcodeproj -scheme smartmarket \
  -destination 'platform=iOS Simulator,name=Mealio Small Screen QA' \
  -only-testing:smartmarketUITests/ReleaseSmokeTests/testOnboardingAndAllTabs \
  test CODE_SIGNING_ALLOWED=NO
```

Backend: `python -m pytest -q` in `smartmarket/smartmarket-backend` (needs
`requirements.lock` + pytest; `cryptography` is required for the account tests).
Last result: 125 passed, 3 skipped.

**Phone** — `scripts/install-phone-test.sh` builds unsigned, signs with the
local development certificate and the phone-test profile, installs and
launches. Plain xcodebuild signing fails because no Apple account is signed in
to Xcode. Background in `docs/PHONE_TESTING.md`.

## Traps met in the session

- **`DEVELOPER_DIR` is mandatory** for every `xcodebuild` / `xcrun` call.
- **The shell is bash 3.2.** Avoid heredocs inside `$(...)` and arrays.
- **Stale UI-test bundle.** After adding or deleting a file in `UITests/`,
  `xcodebuild test` sometimes runs the previous bundle (old tests run, new ones
  are silently skipped). Run `build-for-testing` first, then `test`.
- **`-only-testing` with an unknown test name is silently skipped**, so a typo
  looks like a pass. Check the test name appears in the output.
- **UI tests leave state in the simulator.** A test that hid the bowl left
  `bowlGuideVisible_v2 = false` in the app's preferences on both simulators and
  broke later tests. `simctl spawn … defaults write` does not reach the app's
  sandbox; edit the plist in the app's data container, or pass the value as a
  launch argument.
- **The suite's `tap()` helper rejects controls within 40pt of the top or bottom
  edge** and then scrolls looking for them. Header controls (`home.profile`,
  `mascot.guide`) and the tab bar are exempted by id in the helper.
- **A tap in the first moments after a cold launch can be lost** on the
  simulator; two bowl tests retry once for that reason.
- **SwiftUI `DragGesture` on a horizontal control swallows vertical scrolling.**
  `RulerPicker` uses a UIKit pan that only begins along its own axis.
- **An `.accessibilityElement(children: .contain)` on a view whose children draw
  outside its frame** covers neighbouring controls for XCUITest. `GooMenu`
  dropped its container for that reason.
- **SceneKit screen-space ambient occlusion** made the figure blotchy; it was
  tried and reverted. The seamless look comes from tapered limbs plus mostly
  ambient light.
- **Inline SourceKit errors** ("Cannot find type …") are single-file indexing
  noise. Trust the real build.
